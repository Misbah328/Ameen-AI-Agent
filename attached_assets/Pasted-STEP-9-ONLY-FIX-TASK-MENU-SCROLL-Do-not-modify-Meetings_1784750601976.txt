STEP 9 ONLY — FIX TASK MENU SCROLL

Do not modify Meetings, Task View Details, Dashboard Review Now, Boards, Members, Voting, Permission Counts, or any previously completed fixes.

==================================================
PROBLEM
==================================================

The Tasks section has a scrolling problem.

Possible symptoms:

- The task menu or task tabs do not scroll
- The entire page scrolls instead of the task area
- The task list becomes cut off
- The detail panel prevents scrolling
- Scrolling stops after opening or closing a task
- Mouse wheel or touchpad scrolling does not work
- The sidebar or header moves when only the task content should move
- Horizontal scrolling appears unexpectedly
- The last tasks cannot be reached
- The page jumps back to the top after changing tabs or filters
- Scrolling behaves differently in English and Arabic
- Mobile or smaller screens cannot access all task actions

==================================================
EXPECTED BEHAVIOR
==================================================

The Tasks module must have stable and predictable scrolling.

1. The main application sidebar and top header should remain stable.

2. The Tasks content area should scroll vertically when its content exceeds the available height.

3. The task tabs or filter menu must remain usable and visible.

4. The user must be able to reach the first and last task.

5. Opening the Task Details panel must not disable or break task-list scrolling unless intentionally using a modal lock.

6. Closing Task Details must restore normal scrolling.

7. No unnecessary horizontal scrollbar should appear.

8. Scrolling must work with:

- Mouse wheel
- Touchpad
- Keyboard Page Up and Page Down
- Arrow keys when the task area is focused
- Touch scrolling on smaller screens

9. English and Arabic layouts must both work.

==================================================
INVESTIGATION
==================================================

Inspect:

- Tasks panel HTML structure
- Parent containers of the Tasks module
- Task filter/tab menu
- Task list container
- Task detail side panel
- Main content wrapper
- Sidebar wrapper
- Header wrapper
- CSS height, max-height, min-height, overflow and position rules
- JavaScript that changes body overflow
- Modal or side-panel scroll locking
- Scroll event handlers
- Tab and filter rendering
- Responsive breakpoints
- RTL-specific CSS

Look specifically for:

- overflow: hidden on the wrong parent
- multiple nested scroll containers
- height: 100% without a defined parent height
- fixed or absolute containers without bottom boundaries
- body scroll locking that is not removed
- detail panel overlays intercepting wheel events
- min-height preventing container shrink
- missing min-height: 0 in flex or grid children
- duplicate IDs or selectors
- scrollTop being reset during every render
- horizontal overflow from wide tables or controls

==================================================
FIX REQUIREMENTS
==================================================

1. Use one primary vertical scroll container for the Tasks content.

2. Ensure the Tasks module fits within the viewport below the application header.

3. In flex or grid layouts, add min-height: 0 where required so the scrollable child can shrink.

4. Set appropriate overflow behavior:

- overflow-y: auto for the task content
- overflow-x: hidden unless horizontal scrolling is genuinely required

5. Keep the task filter tabs/menu accessible while scrolling.

Use a sticky task toolbar only if it fits the existing design and does not cover task rows.

6. Do not apply permanent overflow: hidden to body or the main application wrapper.

7. If Task Details intentionally locks the background:

- lock scrolling only while the panel is open
- restore the exact previous overflow state when it closes
- do not leave the page locked after errors or refreshes

8. Preserve the user’s scroll position when:

- Opening and closing Task Details
- Changing a task’s status
- Performing a quick update
- Returning from Dashboard to Tasks

9. For filters or tabs:

- If changing filters intentionally resets scroll, reset only the task-list container
- Do not scroll the entire application page to the top

10. Prevent the detail panel from intercepting scroll events when it is closed.

11. Ensure the last task row and its action buttons are fully reachable and not hidden behind fixed elements.

12. Keep RTL and mobile layouts functional.
