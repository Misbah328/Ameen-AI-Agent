STEP 10 ONLY — FIX ESC KEY NOT CLOSING POLICY MODAL

Do not modify Tasks, Meetings, Dashboard Review Now, Boards, Members, Voting, Search, Autofill, or any previously completed fixes.

==================================================
PROBLEM
==================================================

In the Policies module, pressing the Escape key does not close the open Policy modal.

Possible symptoms:

- ESC does nothing
- ESC closes the wrong layer
- ESC works only after clicking inside the modal
- ESC works once but not after reopening
- ESC closes a dropdown but leaves the modal stuck
- ESC closes the modal but leaves the overlay visible
- Body or application scrolling remains locked after closing
- ESC triggers an unrelated action
- ESC behaves differently in English and Arabic
- ESC does not work in create, edit, or view mode
- Nested dialogs or confirmation prompts interfere with the Policy modal

==================================================
EXPECTED BEHAVIOR
==================================================

When a Policy modal is open:

1. Pressing Escape should close the topmost eligible Policy modal.

2. ESC must work regardless of which field or control currently has focus.

3. ESC should work in:

- Create Policy modal
- Edit Policy modal
- View Policy modal
- Any existing Policy details modal
- Any Policy-related side panel that is intended to behave as a modal

4. ESC must not close the modal when:

- A nested confirmation dialog is open and should receive ESC first
- A date picker, dropdown, select menu, autocomplete, file picker, or nested popup is actively open and is designed to consume ESC
- A destructive operation is actively processing and closing would create an unsafe state

5. When the modal closes:

- The modal receives its closed state
- The overlay/backdrop disappears
- Focus returns to the element that opened the modal
- Body/application scrolling is restored correctly
- No stale keyboard listener remains
- No duplicate listener is created after reopening
- No form data is submitted accidentally
- No unsaved data is silently destroyed if the application already has a confirmation mechanism

6. ESC must not affect the page when no Policy modal is open.

Look specifically for:

- Event handler removed too early
- Event handler never removed
- Duplicate listeners after multiple opens
- A child control calling stopPropagation()
- Modal state not synchronized with DOM classes
- Close function removing only the modal but not the overlay
- Body overflow not restored
- Competing global ESC handlers
- Wrong z-index or modal stack order
- Focus-trap code blocking Escape

==================================================
IMPLEMENTATION REQUIREMENTS
==================================================

1. Reuse the existing Policy modal close function.

Do not create a second independent close path if a correct close function already exists.

2. Add a reliable keydown handler for Escape.

Use:

event.key === "Escape"

Support legacy fallback only if the codebase already requires it.

3. The handler must check that:

- A Policy modal is currently open
- It is the topmost eligible modal
- No nested popup should consume ESC first
- The modal is not in a protected processing state

4. Avoid duplicate listeners.

Use one of these patterns:

- One global delegated keydown listener
- Register on modal open and remove on modal close
- AbortController-based listener cleanup

Choose the pattern that best fits the existing architecture.

5. Restore focus.

Before opening the modal, store the triggering element.

After closing with ESC, return focus to that element if it still exists and is visible.

6. Preserve unsaved-change behavior.

If the existing close button or backdrop prompts the user about unsaved changes, ESC must use the same close function and trigger the same protection.

7. Restore scrolling.

If opening the Policy modal changes:

- document.body.style.overflow
- application wrapper overflow
- scroll position
- modal scroll lock

restore the exact previous state on close.

8. Clear modal state completely.

After ESC closes the modal:

- open class removed
- aria-hidden updated
- aria-modal state correct
- backdrop removed/hidden
- focus trap removed
- event listener cleaned up
- internal selected policy ID reset only if existing close logic already does so

9. Accessibility requirements:

- Modal uses role="dialog" or role="alertdialog"
- aria-modal="true" while open
- Initial focus moves into the modal
- ESC closes unless intentionally blocked
- Focus returns to the opener

10. Do not change the visual design.
