STEP 8 ONLY — FIX DASHBOARD “REVIEW NOW” BUTTON

Do not modify Meetings, Tasks View Details, Boards, Members, Voting, Permission Counts, or any previously completed fixes.

==================================================
PROBLEM
==================================================

The “Review Now” button on the Dashboard does not work correctly.

Possible symptoms:

- Nothing happens when clicked
- It opens the wrong record
- It opens a generic list instead of the exact item
- It opens stale data from a previously selected item
- It works only once
- It opens a blank panel or endless loading state
- The button points to the wrong module
- The record cannot be found after refresh

==================================================
EXPECTED BEHAVIOR
==================================================

When the user clicks “Review Now”:

1. Identify the exact record represented by that dashboard card or row.
2. Open the correct module.
3. Open the exact record requiring review.
4. Show the correct review stage and available actions.
5. Never display stale content from a previously opened record.

The button may represent:

- Meeting minutes review
- Attendee review
- Policy review
- Resolution review
- Circular resolution
- Document approval
- Governance approval item
- Another pending-review record

Do not assume the type. Inspect the dashboard data and determine the correct destination from the record metadata.

==================================================
INVESTIGATION
==================================================

Inspect:

- Dashboard “Review Now” button HTML
- Dashboard card/row rendering function
- Button onclick handler
- Record ID passed by the dashboard
- Record type/module metadata
- Review stage/status metadata
- Destination panel or route
- Existing open-detail or open-review functions
- API endpoint used to populate dashboard review items
- Loading, error, and permission states
- Event listener duplication
- Cached selected-record state

Determine whether the failure is caused by:

- Missing click handler
- Wrong ID
- Wrong record type
- Hard-coded destination
- Generic module navigation without opening the item
- Stale selected-record state
- Cache miss
- Async race condition
- Missing destination function
- Incorrect data attributes
- Mock data not matching API data

==================================================
FIX REQUIREMENTS
==================================================

1. Pass both the exact record ID and record type explicitly.

2. Create or use one shared function such as:

openReviewItem(recordType, recordId)

Do not duplicate review-opening logic across dashboard widgets.

3. Map each supported record type to the correct module and detail/review function.

4. Load fresh record data from the API before rendering where necessary.

5. Confirm the returned record ID matches the requested ID.

6. Clear old review content before loading a new record.

7. Prevent race conditions:
If Review Item A is loading and the user clicks Review Item B, A must not overwrite B.

8. Add clear states:

- Loading
- Record not found
- Permission denied
- Unsupported review type
- API error

9. Keep the close/back action visible and functional.

10. Clicking “Review Now” must not automatically approve, reject, submit, sign, change status, or create audit entries.

11. Existing review actions inside the destination screen must continue to work normally.

12. Do not create duplicate dashboard items or duplicate review records.

- Approve the item
- Reject the item
- Submit a review
- Change workflow stage
- Change status

Open, close, and reopen the same review item several times.
